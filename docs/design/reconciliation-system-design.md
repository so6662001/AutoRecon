## 一、项目背景与目标

### 1.1 业务背景

钢铁行业交易具有**大宗、高频、多品规、多批次**的特点，买卖双方在一个结算周期内可能产生数十甚至数百笔交易。传统对账依赖线下 Excel 传递、人工核对，存在以下痛点：

| 痛点 | 影响 |
|------|------|
| 对账周期长 | 平均 5-10 个工作日完成一轮对账 |
| 差异排查难 | 多品规/多批次场景下人工比对效率极低 |
| 沟通成本高 | 电话、微信、邮件多渠道反复沟通 |
| 确认无凭证 | 双方确认结果缺乏法律效力 |
| 催收脱节 | 对账完成后催款依赖人工跟进，容易遗漏 |

### 1.2 项目目标

构建一套 **"ERP 驱动、模板化生成、自动化比对、电子签章确认、智能催收闭环"** 的线上对账系统，将对账周期从 **5-10 天缩短至 1-2 天**，异议处理效率提升 **60%** 以上。

### 1.3 核心价值主张

```
卖家 ERP 发起 → 自动拉取数据 → 模板化生成对账单 → 自动推送买家
→ 买家人工审核/ERP自动比对 → 无异议电子签章 → 有异议在线协商
→ 签章完成触发智能催收 → 款项到账闭环
```

## 二、用户角色与权限模型

### 2.1 角色定义

| 角色 | 说明 | 关键能力 |
|------|------|----------|
| **卖家管理员** | 卖方企业管理人员 | 模板配置、对账规则设定、催收策略配置 |
| **卖家对账员** | 卖方对账业务人员 | 发起对账、处理异议、跟进催收 |
| **买家管理员** | 买方企业管理人员 | ERP 对接配置、审核流程设定、签章授权 |
| **买家对账员** | 买方对账业务人员 | 审核对账单、提出异议、确认签章 |
| **平台运营** | 平台管理人员 | 系统配置、数据监控、异常介入 |

### 2.2 权限矩阵

```
                     模板管理  发起对账  审核对账  签章  催收配置  异议处理
卖家管理员              ✓        ✓        -       ✓      ✓        ✓
卖家对账员              -        ✓        -       -      -        ✓
买家管理员              -        -        ✓       ✓      -        ✓
买家对账员              -        -        ✓       △      -        ✓
平台运营                ✓        -        -       -      -        ✓

✓ = 完全权限  △ = 受限权限（需授权）  - = 无权限
```

| **notify-svc** | 站内信、短信、邮件、企微/钉钉通知 | 消息队列、多渠道适配 |
| **audit-svc** | 操作日志、变更追踪 | AOP 切面、事件溯源 |

### 5.4 自动比对规则设计

比对引擎是系统的核心智能模块，需要处理钢铁行业的特殊场景：

#### 比对维度

| 比对维度 | 匹配规则 | 容差设定 |
|---------|---------|---------|
| **单据匹配** | 按合同号/订单号精确匹配 | — |
| **品名规格** | 标准化后精确匹配 + 别名映射 | 支持配置别名表 |
| **数量** | 数值比对 | 允许设置容差（如 ±0.5%） |
| **重量** | 数值比对 | 允许设置容差（如 ±0.3%，钢铁行业过磅差异） |
| **单价** | 数值比对 | 允许设置容差（如 ±1 元） |
| **金额** | 数值比对 | 允许设置容差（如 ±10 元） |
| **日期** | 日期比对 | 允许设置天数容差（如 ±3 天） |

#### 比对结果分类

```
比对结果
  ├── 完全匹配     ← 所有维度均在容差范围内
  ├── 部分匹配     ← 关键字段匹配，非关键字段有差异
  ├── 卖方多出     ← 卖方有此明细，买方无对应记录
  ├── 买方多出     ← 买方有此明细，卖方无对应记录
  └── 金额差异     ← 匹配到记录但金额超出容差
```

#### 容差规则配置（企业级）

每个买卖关系可以独立配置容差规则，满足不同客户的对账精度要求：

```
容差配置示例:
{
  "weight_tolerance_type": "percentage",   // percentage | absolute
  "weight_tolerance_value": 0.3,           // 0.3% 或 0.3吨
  "amount_tolerance_type": "absolute",
  "amount_tolerance_value": 10,            // 10元
  "date_tolerance_days": 3,                // 3天
  "auto_confirm_when_matched": true,       // 全部匹配时自动确认
  "match_priority": ["contract_no", "order_no", "delivery_no"]  // 匹配优先级
}
```

**签章安全设计要点：**
- 采用可信第三方签章服务（如 e签宝、法大大），具备法律效力

## 十、数据安全与合规设计

### 10.1 数据安全

| 维度 | 措施 |
|------|------|
| **传输安全** | 全链路 HTTPS/TLS 1.3 加密 |
| **存储安全** | 敏感字段 AES-256 加密存储（金额、账号等） |
| **访问控制** | RBAC 权限模型 + 数据行级隔离（企业维度） |
| **API 安全** | JWT Token + 接口签名 + 频率限制 |
| **ERP 连接安全** | 连接凭证加密存储、最小权限原则 |
| **审计追溯** | 全操作审计日志，保留期限 ≥ 3 年 |

### 10.2 电子签章合规

| 要素 | 说明 |
|------|------|
| **法律依据** | 《电子签名法》、《民法典》电子合同相关条款 |
| **实名认证** | 企业工商认证 + 法人/经办人实名 |
| **意愿确认** | 签章前短信验证码 / 人脸识别 确认签署意愿 |
| **防篡改** | PDF 数字签名 + 时间戳 |
| **存证** | 签署过程全记录 + 第三方存证（可选区块链存证） |

## 十三、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| ERP 系统接口多样，适配成本高 | 集成周期延长 | Phase 1 先支持 REST + Excel 导入；逐步增加适配器 |
| 比对规则复杂，钢铁行业品规命名不统一 | 比对准确率低 | 引入别名映射表 + 模糊匹配 + 人工确认兜底 |
| 电子签章法律效力认知不足 | 客户接受度低 | 选用权威第三方签章服务，提供法律效力说明 |
| 历史数据迁移复杂 | 上线初期体验差 | 提供历史对账单批量导入工具 |
| 买方配合度不足 | 流程推进困难 | 设计催促提醒机制 + 超时自动确认规则（可选） |

## 十四、优化建议（超出基础需求）

### 14.1 智能化增强

| 功能 | 说明 | 价值 |
|------|------|------|
| **智能催收评分** | 基于历史回款行为对买方进行信用评分，调整催收策略优先级 | 提升催收效率，降低坏账 |
| **异议预测** | 分析历史异议数据，在生成对账单时预警可能引起异议的明细 | 减少异议发生率 |
| **自动容差学习** | 根据历史比对结果自动优化容差参数 | 减少人工调参 |
| **重量差异归因** | 结合过磅数据、运输损耗系数自动分析重量差异原因 | 加速异议处理 |

### 14.2 业务闭环增强

| 功能 | 说明 | 价值 |
|------|------|------|
| **对账结果反写ERP** | 对账完成后自动在双方 ERP 生成应收/应付凭证 | 消除手工录入 |
| **发票关联** | 对账单关联发票信息，实现"账-票-款"三单匹配 | 财务合规 |
| **保理融资对接** | 已签章对账单作为应收账款凭证对接保理/供应链金融 | 加速资金周转 |
| **超时自动确认** | 买方超过 N 天未处理，系统自动视为确认（需提前约定） | 防止流程卡死 |

### 14.3 体验优化

| 功能 | 说明 |
|------|------|
| **批量对账** | 支持卖方一次选择多个买家批量生成对账单 |
| **定期自动对账** | 按设定规则（每月1日）自动发起对账 |
| **对账日历** | 可视化展示各客户对账周期和进度 |
| **移动端审批** | 买方管理者可在手机端审批签章 |
| **对账提醒订阅** | 买方可订阅对账进度通知偏好 |
