# 企业数据授权与合规设计方案

> 版本: v1.0  
> 日期: 2026-03-21  
> 适用: 对账通(AutoRecon) + 提货通(PickupExpress)

---

## 一、问题分析

```
数据归属: 合同/对账单/付款/提货/结算等业务数据 → 属于"企业"而非"个人"
数据使用: 平台需要用这些数据做AI训练/行业指数/信用评估等

问题:
├── 如果让每个员工(对账员/财务/销售)去授权 → 他们没有代表企业的权力
├── 如果让管理员一个人授权所有 → 权力太集中，有风险
├── 如果不做授权 → 法律合规风险(《个人信息保护法》《数据安全法》)
└── 如果操作太复杂 → 影响上线速度

核心区分:
├── 企业业务数据(合同/对账/付款/提货) → 需要"企业授权"
├── 个人工作数据(登录/操作/浏览行为) → 需要"个人同意"
└── 两者授权主体和流程应该分开
```

## 二、两级授权模型

```
┌──────────────────────────────────────────────────────────────────┐
│                     两级数据授权体系                               │
│                                                                  │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  第一级: 企业数据授权 (企业管理员代表企业)                    │  │
│  │                                                            │  │
│  │  授权主体: 企业管理员 (必须完成实名认证)                     │  │
│  │  授权范围: 企业业务数据的使用授权                            │  │
│  │  授权时机: 企业入驻/首次使用时 (一次性)                      │  │
│  │  授权方式: 电子签章 (具备法律效力)                           │  │
│  │  变更时: 数据用途更新 → 仅通知管理员重新确认                 │  │
│  │  效力: 覆盖该企业下所有用户和数据                            │  │
│  │                                                            │  │
│  │  授权项 (可勾选, 分项授权):                                  │  │
│  │  ├── ☑ 基础服务 (必选, 不可取消)                            │  │
│  │  │   提供对账/提货/催收等核心服务                             │  │
│  │  ├── ☑ AI模型训练 (可选)                                    │  │
│  │  │   脱敏后用于异议预测/容差学习/催收策略等模型训练            │  │
│  │  ├── ☑ 行业指数 (可选)                                      │  │
│  │  │   脱敏聚合后用于行业基准/趋势报告                          │  │
│  │  ├── ☑ 信用评估 (可选)                                      │  │
│  │  │   用于企业信用评分/供应链金融风控                          │  │
│  │  ├── ☑ 商业洞察 (可选)                                      │  │
│  │  │   脱敏聚合后用于市场分析/推荐匹配                          │  │
│  │  └── ☑ 异常监测 (建议开启)                                  │  │
│  │      用于交易异常识别/防欺诈                                  │  │
│  └────────────────────────────────────────────────────────────┘  │
│                                                                  │
│  ┌────────────────────────────────────────────────────────────┐  │
│  │  第二级: 个人使用确认 (每个用户)                              │  │
│  │                                                            │  │
│  │  确认主体: 每个系统用户 (员工)                               │  │
│  │  确认范围: 个人层面的平台使用条款                             │  │
│  │  确认时机: 首次登录 / 协议更新时                              │  │
│  │  确认方式: 点击确认 (轻量操作)                               │  │
│  │  确认内容:                                                  │  │
│  │  ├── 用户服务协议 (个人使用规范)                             │  │
│  │  └── 隐私政策 (个人信息处理)                                │  │
│  │  注意: 不包含企业数据授权(那是管理员的事)                     │  │
│  └────────────────────────────────────────────────────────────┘  │
│                                                                  │
│  两级关系:                                                       │
│  ├── 企业授权 = 授权平台使用企业的业务数据 (管理员代表企业签)      │
│  ├── 个人确认 = 个人同意平台的使用条款 (每人自己点)               │  
│  ├── 企业授权是前提: 没有企业授权, 数据不能用于AI/指数等           │
│  ├── 个人确认是底线: 没有个人确认, 不能使用系统                   │
│  └── 两者互不替代, 各管各的范围                                  │
└──────────────────────────────────────────────────────────────────┘
```

## 三、企业管理员授权资格

```
谁有权代表企业授权?

方案: 分级授权 + 二次确认

┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  初始授权 (企业入驻时):                                       │
│  ├── 授权人: 企业实名认证时的管理员                           │
│  ├── 前提: 该管理员已完成个人实名认证                         │
│  ├── 方式: 注册流程中展示授权条款 → 电子签章确认               │
│  └── 效力: 代表企业同意数据使用条款                           │
│                                                              │
│  授权变更 (数据用途更新时):                                    │
│  ├── 通知: 系统推送给企业管理员 (短信+站内信)                  │
│  ├── 确认: 管理员在系统中查看变更内容 → 确认                  │
│  ├── 拒绝: 管理员可拒绝新增的授权项                          │
│  │   → 被拒绝的授权项不对该企业生效                           │
│  │   → 不影响已授权项和基础服务                               │
│  └── 超时: 30天未处理 → 提醒3次后冻结新增授权项               │
│      (不冻结基础服务, 不影响正常使用)                          │
│                                                              │
│  授权撤回:                                                    │
│  ├── 管理员可随时在"企业设置"中撤回任意可选授权               │
│  ├── 撤回后: 平台在30天内停止对该企业数据的对应用途           │
│  ├── 已产出的脱敏聚合结果不受影响(无法反向识别)               │
│  └── 基础服务授权不可撤回(否则无法提供服务)                   │
│                                                              │
│  风控:                                                        │
│  ├── 管理员变更 → 新管理员自动继承已有授权                    │
│  ├── 企业注销 → 全部授权自动终止                              │
│  └── 授权操作全程审计日志(不可删改)                           │
└──────────────────────────────────────────────────────────────┘
```

## 四、数据模型

### 企业数据授权表 (enterprise_data_authorization)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| enterprise_id | BIGINT | 企业ID |
| authorization_type | VARCHAR(30) | 授权类型: BASIC_SERVICE / AI_TRAINING / INDUSTRY_INDEX / CREDIT_ASSESSMENT / BUSINESS_INSIGHT / ANOMALY_DETECTION |
| authorized | TINYINT | 是否授权: 0-否 1-是 |
| authorized_by | BIGINT | 授权人(管理员用户ID) |
| authorized_at | DATETIME | 授权时间 |
| authorization_method | TINYINT | 授权方式: 1-注册时签章 2-管理员确认 3-变更确认 |
| ip_address | VARCHAR(50) | 授权时IP |
| user_agent | VARCHAR(500) | 授权时设备 |
| revoked | TINYINT | 是否已撤回: 0-否 1-是 |
| revoked_at | DATETIME | 撤回时间 |
| revoked_by | BIGINT | 撤回人 |
| snapshot_url | VARCHAR(500) | 授权条款快照(OSS) |
| version_no | VARCHAR(20) | 授权时的条款版本号 |

### 企业授权变更通知表 (authorization_change_notification)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| enterprise_id | BIGINT | 企业ID |
| change_type | VARCHAR(30) | 变更类型(新增授权项/条款更新) |
| change_summary | VARCHAR(500) | 变更摘要 |
| new_authorization_types | VARCHAR(200) | 新增的授权类型(逗号分隔) |
| notified_user_id | BIGINT | 通知的管理员ID |
| notified_at | DATETIME | 通知时间 |
| response_status | TINYINT | 响应: 0-待处理 1-已确认 2-已拒绝 3-超时 |
| responded_at | DATETIME | 响应时间 |
| response_detail | VARCHAR(500) | 响应详情(拒绝原因等) |

## 五、法律依据

| 条款 | 法律依据 |
|------|---------|
| 企业管理员代表企业授权 | 《民法典》第61条: 法定代表人/授权代理人行为代表企业 |
| 分项授权(可选) | 《个人信息保护法》第15条: 处理个人信息需取得同意 |
| 撤回权 | 《个人信息保护法》第15条: 有权撤回同意 |
| 数据用途明示 | 《个人信息保护法》第17条: 明确告知处理目的、方式 |
| 最小必要原则 | 《个人信息保护法》第6条: 限于实现处理目的最小范围 |
| 脱敏处理 | 《数据安全法》第21条: 重要数据加强保护 |
| 审计留痕 | 《网络安全法》第21条: 留存网络日志不少于六个月 |
