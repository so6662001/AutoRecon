> **版本**: v1.0  
> **更新日期**: 2026-04-13  
> **适用系统版本**: 提货通 v1.0+

## 前言

### 系统定位

提货通是**从合同签约到提货发货再到结算归档的全流程数字化管理平台**，帮助钢铁贸易商在客户提货的每一步自动记录证据，形成完整的合同→派车→发货→结算证据链。

### 适用角色

| 角色 | 职责范围 | 对应章节 |
|------|---------|---------|
| 卖方管理员 | 系统初始化配置、仓库管理、承运公司管理、模板配置、权限设置 | 第一章、第二章 |
| 卖方销售员 | 合同管理、派车调度、进度跟踪、结算查看 | 第一章、第三章、第四章、第六章 |
| 仓库操作员 | 发货操作、吊装录入、拍照上传、签字确认 | 第五章 |

### 学习目标

完成本手册学习后，您将能够：

1. 熟练使用提货通PC端和H5移动端进行日常操作
2. 独立完成合同创建、派车、发货、结算的全流程操作
3. 理解五层确权机制及证据链的法律意义
4. 掌握常见问题的排查和处理方法

### 预计学习时间

| 角色 | 建议学习时间 |
|------|------------|
| 卖方管理员 | 约 60 分钟（第一章 + 第二章 + 第七章） |
| 卖方销售员 | 约 45 分钟（第一章 + 第三章 + 第四章 + 第六章） |
| 仓库操作员 | 约 30 分钟（第一章 + 第五章） |

## 第一章：快速上手

### 1.1 登录系统

**PC端登录：**

1. 打开浏览器（推荐 Chrome 或 Edge）
2. 访问系统地址（由管理员提供）
3. 输入手机号和密码
4. 点击【登录】按钮

**H5移动端登录：**

1. 在手机浏览器中打开系统H5地址
2. 输入手机号和密码登录
3. 登录后可添加到手机桌面快捷方式，方便下次打开

💡 **提示**：首次登录后建议立即修改初始密码。PC端和H5端使用同一账号，数据实时同步。

⚠️ **注意**：请勿在公共电脑上选择"记住密码"功能，避免账号泄露。

### 1.2 工作台概览

登录成功后默认进入**工作台**页面。工作台是系统的全局概览面板，分为三个区域：

#### 五个统计卡

工作台顶部横向排列5个统计卡片，含义如下：

| 统计卡 | 颜色 | 说明 |
|--------|------|------|
| 合同总数 | 蓝色 | 当前有效合同的总数量 |
| 提货中 | 橙色 | 正处于提货流程中（已派车但尚未完成发货）的提货单数量 |
| 发货中 | 紫色 | 仓库正在执行发货操作的提货单数量 |
| 待结算 | 红色 | 发货完成但尚未生成或确认结算单的数量 |
| 本月提货量(吨) | 绿色 | 当月累计提货的总重量（吨） |

💡 **提示**：关注"待结算"数字变化，及时跟进结算可以加快回款速度。

#### 应收概览仪表盘

位于工作台中部左侧，以半圆仪表盘展示：

- **指针位置**：当前应收总额占目标额度的百分比
- **数值显示**：当前应收账款总金额（¥）
- 帮助您快速掌握整体应收状况

#### 提货趋势图

位于工作台中部右侧，以柱状图展示：

- **横轴**：近6个月的月份
- **纵轴**：每月提货重量（吨）
- 帮助您了解提货量变化趋势，辅助业务决策

#### 最近动态时间线

位于工作台底部，以时间线形式展示最近的业务事件，包括：

- **提货**：提货单发货/完成事件
- **签约**：合同签约完成事件
- **结算**：结算单生成事件
- **派车**：派车分配事件

每条动态都有【查看】链接，点击可跳转到对应合同或提货单详情。

### 1.3 导航说明

#### 菜单结构

系统左侧为深色导航栏，顶部显示"提货通"品牌标识。菜单结构如下：

💡 **提示**：点击左侧导航栏顶部的折叠按钮可以收起菜单，获得更大的工作区域。

#### 移动端H5使用

仓库操作员和销售员可使用手机H5端完成大部分日常操作：

- **H5发货助手**：仓库操作员在手机浏览器打开即可扫码发货，无需安装任何App
- **卖方H5端**：销售员可在手机上查看合同、跟踪提货进度
- **司机端**：驾驶员使用微信小程序操作

⚠️ **注意**：H5端建议使用手机自带浏览器或微信内置浏览器打开，避免使用低版本浏览器导致兼容性问题。

## 第二章：系统初始化配置（管理员）

> 本章面向**卖方管理员**，完成系统上线前的基础配置。

### 2.1 仓库管理

路径：**仓库与物流 → 仓库管理**

#### 添加仓库

1. 点击页面顶部【新增仓库】按钮
2. 在弹出的对话框中填写以下信息：

| 字段 | 必填 | 说明 |
|------|------|------|
| 仓库名称 | ✅ | 仓库的显示名称，例如"上海宝山仓" |
| 编码 | 否 | 仓库编码，用于ERP对接时的标识映射 |
| 地址 | 否 | 仓库详细地址 |
| 联系人 | 否 | 仓库负责人姓名 |
| 电话 | 否 | 联系电话 |
| GPS坐标 | 否 | 格式为"经度,纬度"，用于定位 |

3. 点击【确定】完成添加

#### 设置默认发货模式

每个仓库需要配置默认发货模式，系统支持以下四种模式：

| 发货模式 | 适用场景 | 说明 |
|---------|---------|------|
| WMS | 已有WMS仓库管理系统的仓库 | 通过WMS接口自动同步发货数据 |
| H5助手 | 无WMS的普通仓库（推荐） | 仓库工人用手机浏览器扫码操作 |
| 第三方 | 使用第三方物流仓的情况 | 通过第三方系统对接 |
| 驾驶员确认 | 简易模式 | 由提货驾驶员在微信小程序上确认收货内容 |

**设置步骤**：在仓库列表中点击对应仓库的【编辑】按钮 → 选择"默认发货模式" → 保存。

💡 **提示**：如果仓库没有WMS系统，推荐使用"H5助手"模式——操作简单，仓库工人用手机即可完成发货录入。

#### 仓库员账号配置

仓库操作员需要独立的登录账号：

1. 联系系统管理员创建仓库操作员账号
2. 将账号绑定到对应仓库
3. 仓库操作员使用独立账号登录H5发货助手

⚠️ **注意**：仓库员只能看到分配给他的仓库的提货单数据，无法访问其他仓库和合同信息。

### 2.2 承运公司管理

路径：**仓库与物流 → 承运公司**

#### 添加承运公司

当您使用"承运公司派车"模式时，需要提前维护承运公司信息：

1. 进入承运公司管理页面
2. 点击【新增承运公司】
3. 填写公司名称、联系人、联系电话等信息
4. 保存

#### 车辆和驾驶员信息

承运公司下可以维护常用车辆和驾驶员：

- **车牌号**：关联到具体车辆
- **驾驶员姓名**：驾驶员真实姓名
- **驾驶员电话**：用于接收提货码和确权短信
- **身份证号**：可选，用于身份验证

💡 **提示**：提前维护好承运公司的车辆和驾驶员信息，派车时可以快速选择，不必每次手动输入。

### 2.3 合同模板管理

路径：**系统设置 → 合同模板**

#### 标准模板 vs 自定义模板

系统提供两类合同模板：

| 类型 | 说明 |
|------|------|
| 系统预置模板 | 系统内置的标准模板，包含留货、订货、框架、简易四种类型 |
| 自定义模板 | 根据企业需求自行创建的模板 |

#### 模板字段配置

创建或编辑模板时，可以配置：

1. **模板名称**：例如"标准留货合同模板"
2. **合同类型**：留货 / 订货 / 框架 / 简易
3. **来源**：系统 / 自定义
4. **产地字段**：开关控制是否在合同中显示产地信息
5. **条款优先级**：正文优先 / 附件优先——决定条款冲突时的解释顺序
6. **设为默认**：该模板是否作为默认模板

**操作步骤**：

1. 点击【新增模板】
2. 填写模板名称，选择合同类型
3. 根据需要开启产地字段
4. 设置条款优先级
5. 如需设为默认，打开"设为默认"开关
6. 点击【确定】保存

#### 平台附加条款（框架合同+提货确认单架构）

提货通采用**"框架合同+提货确认单"**的法律架构：

- **框架合同**：约定交易规则，包含"以实际发货数据为准"的关键条款
- **提货确认单**：每次提货自动生成，记录实际发货的品规、数量、重量

平台的交易服务条款以附件形式自动附加到合同中，不影响您自有合同的格式和内容。

⚠️ **注意**：合同模板中建议保留"以实际发货为准"的条款，这是确保逐吊记录作为结算依据的法律基础。

### 2.4 确认时效配置

路径：**系统设置 → 确认时效**

确认时效决定了客户在收到通知后的默认确认时间。超过时效未回复，系统自动视为确认。

#### 各场景默认天数

系统预设了四种场景的确认时效：

| 场景 | 默认值 | 说明 |
|------|--------|------|
| 无差异 | 24小时 | 发货数据与合同一致时，客户确认时限 |
| 品规变更 | 24小时 | 实际发货品规与合同有差异时的确认时限 |
| 数量超差 | 24小时 | 实际数量超出合同约定范围时的确认时限 |
| 结算确认 | 24小时 | 结算单推送后客户的确认时限 |

#### 平台允许范围

- 时效单位可选择"小时"或"天"
- 每种场景可独立配置
- 支持按客户设置专属时效（选择具体客户后编辑）
- 可设置"到期前提醒"时间（小时），在超时前提前通知

#### 法律建议

💡 **提示**：建议"无差异"场景设置24小时，"品规变更"和"数量超差"场景设置48~72小时，给客户充足的核实时间。时效过短可能在法律上被认为不合理。

**操作步骤**：

1. 在时效配置页面选择"平台默认"或选择具体客户
2. 点击对应场景的【编辑】按钮
3. 设置超时值和单位
4. 设置到期前提醒时间
5. 点击【确定】保存

### 2.5 授权提货人管理

路径：**确权管理 → 授权提货人**

#### 预登记驾驶员

预登记是提货确权的第一层保障。将客户常用的提货驾驶员提前录入系统，后续提货时系统可自动匹配验证。

**登记信息包括**：

- 驾驶员姓名
- 手机号码
- 身份证号（可选）
- 常用车牌号
- 所属客户

#### 身份信息采集

系统在发货环节可自动采集驾驶员的身份信息：

- 身份证正面拍照
- 人脸照片
- 车牌照片

这些信息作为确权证据的一部分归档保存。

💡 **提示**：建议与每个客户沟通，将其常用提货驾驶员全部预登记。预登记的驾驶员提货时确权流程更顺畅，未预登记的驾驶员会触发加强确权（如电话确认）。

### 2.6 数据授权设置

路径：**系统设置 → 数据授权**

数据授权用于控制不同角色和人员对业务数据的访问权限：

- **按角色授权**：不同角色看到不同范围的数据
- **按客户授权**：销售员只能看到自己负责的客户数据
- **按仓库授权**：仓库操作员只能看到分配给自己的仓库数据

⚠️ **注意**：数据授权配置关系到业务数据安全，修改前请充分评估影响范围。

## 第三章：合同管理

### 3.1 两种合同类型

提货通支持两种核心合同类型：

| 类型 | 编码 | 业务场景 | 签约要求 |
|------|------|---------|---------|
| 留货合同 | reserved | 货物已在仓库，客户随时可提 | 可选（静默模式） |
| 订货合同 | order | 客户下单后生产或调拨 | 必须签约 |

**留货合同**适用于大部分钢贸场景：货物已到仓库，客户按需分批提货。

**订货合同**适用于定制生产或远期交付的场景：需要双方先签约确认交易条款。

💡 **提示**：如果您的业务以现货交易为主，大部分合同应使用"留货"类型。留货合同的流程更简便，客户不需要额外操作。

### 3.2 创建合同

路径：**合同管理 → 合同列表**

#### 从ERP同步

如果您的企业已对接ERP系统，合同可以自动同步：

1. ERP中合同生效后，数据自动推送到提货通
2. 提货通自动创建对应的合同记录
3. 合同状态自动设为"可提货"（留货合同）或"待签约"（订货合同）

💡 **提示**：ERP同步的合同不需要手动创建，系统会自动完成。同步时间取决于ERP对接的频率设置。

#### 手动创建

暂未对接ERP的企业可以手动创建合同：

1. 点击合同列表页上方的操作按钮
2. 选择合同类型（留货/订货/框架）
3. 填写合同信息
4. 保存

#### 合同字段说明

| 字段 | 说明 |
|------|------|
| 合同号 | 合同编号，ERP同步时自动填充 |
| 合同类型 | 留货 / 订货 / 框架 |
| 客户名称 | 买方企业名称 |
| 品规简要 | 货物品种和规格的摘要信息 |
| 合同数量 | 约定的货物件数 |
| 合同重量(吨) | 约定的货物总重量 |
| 合同金额 | 合同约定的总金额 |
| 已提重量 | 已完成提货的累计重量 |
| 未提重量 | 尚未提货的剩余重量 |
| 已付金额 | 客户已支付的累计金额 |
| 产地 | 货物产地（如模板开启了产地字段） |
| 单价 | 每吨单价 |
| 仓库 | 货物存放的仓库 |

#### 合同状态流转

合同在生命周期中经历以下状态：

```
可提货 → 待签约 → 已签约 → 提货中 → 已提完 → 已结清 → 已关闭
```

| 状态 | 含义 |
|------|------|
| 可提货 | 留货合同默认状态，客户可以直接派车提货 |
| 待签约 | 订货合同创建后的初始状态，需要双方签约 |
| 已签约 | 双方完成电子签约 |
| 提货中 | 合同下已有正在进行的提货单 |
| 已提完 | 合同约定数量已全部提完 |
| 已结清 | 所有结算已完成，款项已到位 |
| 已关闭 | 合同已终止 |

### 3.3 合同签约

#### 在线签约流程

对于订货合同，需要通过在线电子签约：

1. 在合同列表中找到状态为"待签约"的合同
2. 点击操作列的【发起签约】按钮
3. 系统通过电子签章平台（e签宝/法大大）发起签约
4. 买方收到签约通知后在线完成签章
5. 双方签章完成后，合同状态变为"已签约"
6. 签章后的PDF自动归档到证据包

#### 留货合同的静默模式（不强制客户签约）

留货合同采用**静默模式**——ERP合同同步后直接进入"可提货"状态，**客户无需进行任何签约操作**。

这意味着：
- 客户打电话让司机去仓库提货，流程与以前完全一样
- 签约是可选的增强项，不是前提条件
- 系统通过提货记录和确权机制来采集证据

💡 **提示**：静默模式的设计理念是"对客户零阻力"。客户感觉流程没有任何变化，但系统在后台自动采集完整的证据链。

#### 订货合同的必须签约

订货合同**必须**双方完成签约后才能进入提货流程。这是因为：
- 订货涉及生产或采购，需要明确的合同约束
- 签章后的合同PDF是证据链的起点

⚠️ **注意**：发起签约前请确认合同信息无误，签约完成后合同内容不可修改。

### 3.4 查看合同详情

在合同列表中点击任意合同的【查看】按钮，进入合同详情页。

#### 合同信息

详情页顶部展示完整的合同基本信息，包括：
- 合同号、ERP合同号
- 合同类型、客户信息
- 品规、数量、重量、金额
- 签约状态、签章PDF链接
- 仓库、付款条款、交货期限

#### 关联提货单

中部以列表形式展示该合同下的所有提货单：
- 提货单号、状态
- 驾驶员信息、车牌
- 提货重量、金额

#### 提货进度

底部以可视化方式展示提货进度：

**常见问题**

> **Q：合同同步后看不到？**

> **Q：留货合同需要客户签约吗？**

> **Q：合同金额和实际提货金额不一致怎么办？**  
> A：这是正常的。框架合同+提货确认单架构决定了以实际发货数据为准，合同金额仅为预估。

## 第四章：派车与提货

### 4.1 三种派车模式

提货通支持三种派车模式，适用于不同的业务场景：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| 客户派车 | 客户自行安排车辆和驾驶员 | 客户有自己的运输队伍或固定合作司机 |
| 销售派车 | 卖方销售员代为安排车辆 | 客户委托卖方安排运输 |
| 承运公司 | 由指定承运公司安排车辆 | 使用专业物流公司 |

💡 **提示**：大部分钢贸场景使用"客户派车"模式——客户打电话说"明天派车去提货"，销售员在系统中录入司机和车辆信息即可。

### 4.2 创建提货单

路径：**提货管理 → 派车管理 → 【新建派车】**

**操作步骤**：

1. 点击【新建派车】按钮，弹出派车申请对话框
2. **选择合同**：在搜索框中输入合同号，从下拉列表中选择目标合同
3. **选择派车模式**：
   - 客户派车 / 销售派车：需填写车牌号、驾驶员姓名、驾驶员电话、预计到达时间
   - 承运公司：选择已维护的承运公司
4. 点击【确定】提交

**提交成功后**：
- 系统自动生成提货单号
- 自动生成电子提货码
- 驾驶员手机将收到提货码短信

#### 生成提货码

提货码是一个6位数字码，作用：

- 仓库发货时验证提货人身份
- 与合同和提货单唯一绑定
- 一次提货使用一个码，不可重复

#### 提货码有效期

- 提货码有一定的有效期（通常为48~72小时）
- 过期后自动失效，需重新生成
- 驾驶员到仓库时出示提货码即可开始发货

⚠️ **注意**：请确保驾驶员手机号准确，提货码将通过短信发送到该号码。

### 4.3 派车管理

路径：**提货管理 → 派车管理**

- 车牌号、驾驶员姓名

#### 实时监控大屏

## 第五章：仓库发货操作

> 本章面向**仓库操作员**，介绍使用H5发货助手进行仓库发货的完整操作流程。

### 5.1 发货流程概述

系统支持多种发货模式，选择依据如下：

| 发货模式 | 适用条件 | 操作人 | 操作工具 |
|---------|---------|--------|---------|
| WMS | 仓库有自有WMS系统 | WMS操作员 | WMS客户端 |
| H5助手 | 无WMS的仓库（最常用） | 仓库操作员 | 手机浏览器 |
| 第三方 | 使用第三方仓储系统 | 第三方系统 | 自动对接 |
| 驾驶员确认 | 无条件安装设备的简易场景 | 驾驶员 | 微信小程序 |

⚠️ **注意**：发货模式在仓库管理中配置，仓库操作员不需要自行选择，系统会根据仓库配置自动引导操作。

### 5.2 H5发货助手（无WMS仓库）

H5发货助手是专为没有WMS系统的仓库设计的发货工具，仓库工人用手机浏览器即可完成全部操作。

#### 步骤一：扫码/输入提货码验证

1. 在手机浏览器中打开H5发货助手
2. 两种验证方式：
   - **扫码**：点击扫码按钮，扫描驾驶员出示的提货码二维码
   - **手动输入**：在输入框中输入6位提货码
3. 系统验证提货码有效性
4. 验证通过后显示提货单详情（合同号、客户名、货物信息）

💡 **提示**：建议优先使用扫码方式，速度更快且不易出错。

#### 步骤二：逐吊录入

每一吊货物需要独立录入数据：

1. 点击【新增吊装记录】
2. 填写以下信息：

| 字段 | 必填 | 说明 |
|------|------|------|
| 品名 | ✅ | 货物名称，如"热轧卷板" |
| 规格 | ✅ | 规格型号，如"Q235B 5.75*1500" |
| 材质 | 否 | 材质标号 |
| 炉号 | 否 | 钢材炉号 |
| 批次号 | 否 | 生产批次 |
| 件数 | ✅ | 本吊货物件数 |
| 理论重量(吨) | 否 | 理论计算重量 |
| 实际重量(吨) | ✅ | 过磅实际重量 |

3. 点击保存，该吊记录即时上传到服务器
4. 重复以上步骤直到所有吊装完成

💡 **提示**：每吊数据保存后会实时同步到卖方PC端，销售员在办公室即可看到装货进度。

#### 步骤三：拍照上传

发货过程中需要拍摄并上传以下照片：

| 照片类型 | 用途 | 建议 |
|---------|------|------|
| 装载照 | 记录装车现场 | 拍摄整车装载状态，能看清货物摆放 |
| 货物照 | 记录货物信息 | 拍摄货物标牌或标识，能看清品规 |
| 车牌照 | 记录车辆信息 | 拍摄车辆前后车牌，清晰可辨 |
| 磅单照 | 记录过磅数据 | 拍摄地磅称重显示屏或打印磅单 |

⚠️ **注意**：照片是证据包的重要组成部分，请确保拍摄清晰、内容完整。模糊或缺失的照片可能影响证据效力。

#### 步骤四：签字确认

1. 所有吊装记录和照片上传完成后，进入签字确认环节
2. 驾驶员在手机屏幕上手写签名
3. 签字照片自动保存到证据包

#### 步骤五：完成发货

1. 确认所有信息无误后，点击【完成发货】
2. 系统自动执行以下操作：
   - 提货单状态变更为"已完成"
   - 向客户发送提货完成短信通知
   - 自动生成结算单
   - 自动归档证据包
3. 发货完成

💡 **提示**：完成发货后，客户会收到一条短信，内容为"您的提货已完成，共提XX吨，金额XX元"。客户点击短信链接即可查看详情。

### 5.3 WMS集成发货

如果仓库已部署WMS系统，发货数据通过接口自动同步：

1. 仓库操作员在WMS中正常操作出库流程
2. WMS通过API将发货数据（品规、件数、重量）推送到提货通
3. 提货通自动接收并记录每吊数据
4. 销售员在PC端实时查看进度

WMS集成模式下，仓库操作员无需使用H5助手，在原有WMS中操作即可。照片上传和签字确认仍需在H5端或WMS端完成。

### 5.4 提货码验证

#### 5次错误锁定机制

为防止提货码被暴力猜测：
- 连续输入错误提货码**5次**后，该提货单将被**临时锁定**
- 锁定后需联系销售员或管理员手动解锁
- 锁定事件会被记录在系统日志中

#### 过期处理

- 提货码超过有效期后自动失效
- 驾驶员到达仓库时如提货码已过期，需联系销售员重新生成
- 销售员在提货单详情页可操作重新发送提货码

#### 异常情况处理

| 异常情况 | 处理方式 |
|---------|---------|
| 驾驶员未收到提货码 | 联系销售员确认手机号，重新发送 |
| 提货码输入正确但验证失败 | 检查是否过期，联系销售员确认提货单状态 |
| 扫码功能无法使用 | 改用手动输入方式 |
| 网络断开无法验证 | 等待网络恢复，或联系管理员电话确认后手动放行 |

⚠️ **注意**：任何情况下都不应跳过提货码验证环节。未经验证的发货将导致证据链断裂。

### 5.5 发货进度查看

路径：在提货单列表中点击具体提货单 → 进入发货进度页面

#### 进度环

页面顶部展示一个大进度环图：
- **外环进度**：已装吊数占总吊数的百分比
- **中心文字**：已装 X / Y 吊
- **下方数字**：已装 XX.XX 吨

#### 吊装记录表

中部表格展示每一吊的详细数据：

| 列 | 说明 |
|----|------|
| 吊序号 | 第几吊 |
| 品规 | 货物品种规格 |
| 件数 | 本吊件数 |
| 重量 | 实际重量（吨） |
| 时间 | 录入时间 |
| 操作员 | 录入该吊数据的操作员 |
| 标记 | 新增的吊装记录会显示"新"标签 |

#### 已上传照片

底部以网格形式展示所有已上传的照片，点击可放大预览。

**常见问题**

> **Q：发货途中手机没电了怎么办？**  
> A：已保存的吊装记录不会丢失。换一部手机重新登录，继续操作即可。

> **Q：录入数据写错了能修改吗？**  
> A：已上传的吊装记录不可直接修改。如有误，请联系销售员通过"事后补录"功能修正。

> **Q：网络不好数据会丢失吗？**  
> A：不会。H5助手支持断网缓存，数据自动保存在手机本地，网络恢复后自动上传。

## 第六章：结算与证据

### 6.1 自动结算生成

#### 系统自动计算

当一次提货的发货操作完成后，系统会**自动生成结算单**，无需人工干预。

结算计算逻辑：
1. 逐吊实际过磅重量 × 合同单价 = 每吊金额
2. 所有吊的金额汇总 = 本次结算小计
3. 加上税费（根据税率计算）
4. 减去已付款金额（如有预付款）
5. 得出应收金额

#### 结算明细说明

| 字段 | 说明 |
|------|------|
| 结算重量 | 所有吊装记录实际重量之和 |
| 结算金额 | 结算重量 × 单价 |
| 税额 | 根据适用税率计算 |
| 价税合计 | 结算金额 + 税额 |

💡 **提示**：结算以实际过磅重量为准，而非合同约定重量。这也是"框架合同+提货确认单"架构的核心意义。

### 6.2 结算单查看

路径：**结算与证据 → 结算列表**

#### 结算列表

页面顶部展示三个汇总统计卡：
- **待结算数**：待完成结算的数量
- **本月结算额**：当月累计结算金额
- **应收总额**：所有未收回的应收金额

支持按以下条件筛选：
- 结算单号
- 合同号
- 客户名称
- 状态（待结算/已结算/已对账）

#### 结算详情

点击结算列表中的【查看】进入详情页，可以查看：
- 结算单号、关联的合同号和提货单号
- 客户信息
- 结算重量、金额、税额、价税合计
- 客户是否已查看
- 是否已同步到对账系统
- 创建时间

### 6.3 客户确认机制

#### 通知推送

结算单生成后，系统自动通过短信向客户推送通知：
- 短信内容包含提货重量、金额等关键信息
- 客户可点击短信链接查看结算详情
- 客户无需注册或安装App即可查看

#### 默认确认时效

- 结算单推送后，客户在确认时效内可以提出异议
- 超过时效未回复，系统自动视为"已确认"
- 默认时效在"系统设置 → 确认时效"中配置

#### 客户异议处理

如果客户在时效内提出异议：
1. 销售员会收到异议通知
2. 进入结算详情页查看异议内容
3. 与客户沟通核实
4. 根据实际情况进行调整或维持原结算

### 6.4 证据包

路径：提货单详情页 → 证据包

#### 证据包内容

每次提货完成后，系统自动生成完整的证据包，包含以下文件：

| 文件 | 格式 | 说明 |
|------|------|------|
| 签章合同PDF | PDF | 经电子签章的合同文件 |
| 提货单PDF | PDF | 包含提货码、驾驶员信息的提货单 |
| 发货明细 | JSON/PDF | 逐吊发货数据（品规、件数、重量、操作员、时间） |
| 现场照片 | 图片 | 装载照、货物照、车牌照、磅单照 |
| 签字照片 | 图片 | 驾驶员手写签名 |
| 结算单PDF | PDF | 自动生成的结算单 |
| 通知记录 | 数据 | 短信发送记录及送达回执 |

#### 证据完整性验证（Hash校验）

- 系统使用**SHA-256算法**对证据包进行哈希计算
- 哈希值在证据包概览中显示
- 点击【验证证据完整性】按钮可验证数据是否被篡改
- 验证通过显示"证据完整性验证通过"

⚠️ **注意**：证据包一旦归档，任何修改都会导致哈希值变化，从而被系统检测到篡改。

#### 下载证据包

1. 进入证据包页面
2. 点击【下载证据包(ZIP)】按钮
3. 系统生成ZIP文件并下载到本地
4. ZIP文件包含上述所有证据文件

💡 **提示**：建议定期下载重要客户的证据包作为本地备份。在需要法律维权时，可以直接将证据包提交给律师或法院。

#### 证据的法律效力

- **电子签章**：使用e签宝/法大大平台，根据《电子签名法》与纸质签章同等法律效力
- **通知送达**：短信发送记录和送达回执可作为通知送达的证据
- **电话确权录音**：IVR电话确认的录音可作为客户授权提货的证据
- **哈希防篡改**：SHA-256校验证明数据自归档后未被修改
- **时间戳**：所有操作均有服务器时间戳，不可伪造

**常见问题**

> **Q：结算金额和合同金额不一致正常吗？**  
> A：正常。结算以实际过磅重量计算，合同金额是预估值。"框架合同+提货确认单"架构明确约定以实发为准。

> **Q：客户没有确认结算单怎么办？**  
> A：超过确认时效后系统自动视为确认。确认时效可在系统设置中调整。

> **Q：证据包可以作为法院证据吗？**  
> A：可以。电子签章具有法律效力，所有数据均有时间戳和哈希防篡改校验，符合电子证据的法律要求。

## 第七章：确权与风控

### 7.1 五层确权机制

确权是提货通的核心能力之一，用于证明"客户确实授权了这次提货"。系统采用五层递进式确权：

#### 第一层：预登记驾驶员

- 客户提前在系统中登记常用提货驾驶员
- 提货时系统自动匹配驾驶员身份
- 预登记的驾驶员提货，确权等级为"轻度"（LIGHT）

#### 第二层：实时短信确认

- 每次提货开始时，系统自动向客户（买方联系人）发送确权短信
- 短信内容：告知有人正在提货，提货人信息、车牌号等
- 短信有送达回执，证明客户已收到通知

#### 第三层：驾驶员身份采集

- 仓库发货时采集驾驶员身份信息
- 包括身份证正面拍照、人脸照片
- 信息归档到证据包

#### 第四层：IVR电话确认

- 对于未预登记的驾驶员，系统自动拨打客户电话进行确认
- IVR自动语音："XX驾驶员正在您的合同XX下提货，如确认请按1，如不确认请按2"
- 通话全程录音，录音文件归档到证据包
- 最多拨打3次，3次未接按无法确认处理

#### 第五层：交易习惯分析

- 系统分析客户的历史交易数据
- 生成交易习惯报告，包括：
  - 常用驾驶员
  - 提货时间规律
  - 常用车辆
  - 提货频次和数量模式
- 作为辅助证据，证明"这次提货符合客户的一贯交易习惯"

#### 确权强度等级

| 等级 | 编码 | 说明 | 触发条件 |
|------|------|------|---------|
| 轻度 | LIGHT | 预登记驾驶员 + 短信通知 | 驾驶员在预登记名单中 |
| 标准 | STANDARD | 轻度 + 身份采集 | 默认确权等级 |
| 加强 | ENHANCED | 标准 + 电话确认 | 未预登记的驾驶员 |
| 严格 | STRICT | 加强 + 客户主动确认 | 大额交易或高风险客户 |
| 最严格 | STRICTEST | 严格 + 现场视频 | 特殊风控需求 |

💡 **提示**：确权等级由系统根据驾驶员是否预登记、交易金额、客户信用等因素自动判定。管理员也可以为特定客户手动设置更高的确权等级。

### 7.2 交易习惯查看

路径：**确权管理 → 交易习惯**

交易习惯页面展示每个客户的提货行为模式分析：
- 常用提货驾驶员名单
- 提货时间分布（按时段/按星期）
- 平均每次提货量
- 常用车辆列表
- 异常行为标记

### 7.3 确权记录查看

路径：**确权管理 → 确权记录**

确权记录列表展示每次提货的确权详情：

| 列 | 说明 |
|----|------|
| 提货单号 | 对应的提货单 |
| 合同号 | 对应的合同 |
| 司机 | 提货驾驶员姓名 |
| 车牌 | 车辆号牌 |
| 是否预登记 | 该驾驶员是否在预登记名单中 |
| 确权等级 | 轻度/标准/加强/严格/最严格 |
| 短信已发 | 确权短信是否已发送 |
| 电话确认 | 是否进行了电话确认 |
| 电话结果 | 确认/未接/拒绝 |
| 身份采集 | 是否采集了驾驶员身份信息 |
| 确权结果 | 通过/拒绝/待处理 |

点击【查看详情】可以看到：
- 完整的确权信息
- 现场照片
- 电话录音链接（如有）

### 7.4 事后补录

路径：**系统设置 → 事后补录**

对于某些特殊情况（如网络故障、设备故障等），无法在发货现场完成所有数据采集时，可以使用事后补录功能：

1. 在事后补录页面选择对应的提货单
2. 补充缺失的数据（吊装数据、照片、签字等）
3. 提交补录申请
4. 系统记录补录时间和操作人，标记为"事后补录"数据

⚠️ **注意**：事后补录的数据在证据包中会被标记为"补录"，法律效力可能低于实时采集的数据。应尽量避免使用事后补录，优先在现场完成所有数据采集。

**常见问题**

> **Q：未预登记的驾驶员来提货怎么办？**  
> A：可以正常提货。系统会自动触发加强确权——拨打客户电话确认。提货后建议将该驾驶员补录到预登记名单。

> **Q：电话确权拨打了3次客户都没接怎么办？**  
> A：系统记录为"未接"。仓库可以根据管理员配置的策略决定是否继续发货。建议联系销售员与客户沟通后再操作。

> **Q：确权记录中显示"待处理"是什么意思？**  
> A：表示确权流程尚未完成（如电话未拨打或等待客户回复）。需要等待流程完成或人工处理。

## 第八章：常见问题与故障排除

### 8.1 合同问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| ERP合同同步后在系统中看不到 | 同步延迟或对接配置错误 | 等待几分钟后刷新；检查ERP对接配置 |
| 合同状态显示"待签约"但客户未收到签约通知 | 签约尚未发起 | 在合同列表点击【发起签约】 |
| 合同金额显示为0 | ERP同步数据缺少金额字段 | 手动补充合同金额信息 |
| 搜索合同找不到 | 筛选条件未清空 | 点击【重置】清空所有筛选条件后重新搜索 |
| 合同重复 | ERP重复推送 | 联系管理员处理重复数据 |

### 8.2 提货码问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 驾驶员未收到提货码短信 | 手机号错误或短信延迟 | 核实手机号，等待或重新发送 |
| 提货码验证失败 | 码已过期或输入错误 | 核实码的有效期；仔细核对后重新输入 |
| 连续输错被锁定 | 触发5次错误锁定 | 联系销售员或管理员解锁 |
| 提货码过期 | 超过有效期 | 销售员在提货单详情页重新生成提货码 |

### 8.3 发货问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| H5助手打不开 | 浏览器版本过低或网络问题 | 更换浏览器（推荐Chrome）；检查网络 |
| 照片上传失败 | 图片过大或网络差 | 压缩图片后重试；切换到Wi-Fi网络 |
| 吊装数据保存失败 | 网络中断 | 数据已本地缓存，网络恢复后自动上传 |
| 扫码功能无法使用 | 浏览器未授权相机权限 | 在浏览器设置中允许相机权限 |
| 发货中途手机没电 | 设备问题 | 已保存的数据不会丢失，换手机登录继续操作 |
| 录入数据错误 | 人为失误 | 联系销售员通过"事后补录"修正 |

### 8.4 结算问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 发货完成但结算单未生成 | 发货未正式"完成" | 检查是否点击了【完成发货】 |
| 结算金额不对 | 吊装数据录入有误 | 通过事后补录修正数据后重新生成结算 |
| 客户未查看结算单 | 客户未打开短信链接 | 联系客户，告知查看方式 |
| 结算状态一直是"待结算" | 等待系统处理 | 稍等片刻；若长时间未变，联系管理员 |

### 8.5 网络问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 页面加载缓慢 | 网络带宽不足 | 检查网络连接；关闭其他占用带宽的应用 |
| 登录提示超时 | 服务器暂时不可用 | 稍后重试；如持续出现，联系技术支持 |
| 仓库现场无网络 | 偏远仓库信号差 | H5助手支持断网缓存，恢复后自动上传；考虑安装Wi-Fi |
| 实时监控数据不更新 | 自动刷新中断 | 手动点击【刷新】按钮；刷新浏览器页面 |
| 证据包下载失败 | 网络不稳定或文件过大 | 在网络稳定时重试；分次下载 |

💡 **提示**：仓库操作员在信号较差的场所工作时，建议操作前先确认手机有足够的信号和电量。H5助手的断网缓存功能可以保障数据不丢失，但建议尽量在有网络的环境下操作。
